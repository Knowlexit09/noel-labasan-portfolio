Problem & Approach

A small company's manual attendance ledger can create repetitive encoding, hard-to-review late punches and fragmented leave records. This project explores a low-cost QR kiosk workflow backed by familiar Google Sheets instead of a paid attendance platform.

The public demo intentionally uses fictional names and browser-local data. Google Sheets integration is implemented as Apps Script source but requires authorized owner setup and deployment; no company's actual employee database is publicly connected.

Implemented Features

  • Employee creation & editing: unique IDs, names, departments, same-day shifts, grace minutes and deactivate/reactivate controls.
  • Individual QR cards: create, view, copy and download a badge image for each employee.
  • QR Time In & Out: camera scan or pasted credential; validates employee badge, duplicate punches, active status, approved leave and Time In before Time Out.
  • Daily dashboard: active headcount and distinct Present / Late / Absent / On Leave counts with in/out times.
  • Leave records: manager enters approved leave periods, checks overlaps in production and can revoke approvals.
  • Reports: date filtering, employee search, latest punches and CSV export.
  • Editable demo clock: simulate before/after grace cutoff without changing the actual system time; disabled in Google Sheets production edition.
  • Audit & concurrency: production Sheets has audit entries and lock-protected write operations.

Architecture & Data Flow

Client UIHTML/CSS/JavaScript dashboard with camera QR reader; demo runs in localStorage
Apps Script serviceGoogle-account manager allowlist, validation, authenticated RPC and server time
Sheets tablesEmployees, Attendance, Leaves and Audit; owner setup creates tabs automatically

For a real company, the manager deploys the Google Apps Script HTML Service web app. The browser calls google.script.run functions and those functions read/write Google Sheets. The free public GitHub Pages demo uses the same frontend but only local fictional sample data. Both modes are clearly labeled.

Safety, Privacy & Current Limitations

Company attendance should never be exposed as an open public Google Sheet or anonymous Apps Script endpoint. The deployment guide uses a Google-authenticated manager-operated web app and an exact email allowlist, with server-authoritative punch times and Apps Script locks. Test Clock has no effect on production attendance.

QR badges are static bearer credentials. A copied QR can still be presented at an authorized kiosk; this starter project is not a fraud-proof biometric or payroll system. Use supervised scans and additional identity controls before recording high-stakes employee decisions.

The first version assumes same-day shifts, a 30-minute absence cutoff and manually approved leave. Overnight shifts, rotating schedules, payroll, time-off workflows, paid holiday logic, scaled data paging, offline mode, detailed role permissions and legal compliance review are future scope.

Try It & Deploy for a Company

Use the live demo to create fictional staff, simulate different clock times, scan badges, see statuses, and export a CSV. Demo data remains only in your own browser and may be reset.

To connect to a real Google Sheet, follow the owner setup guide, which includes authorization, deployment settings, status definitions, security limits and manual QA scenarios.

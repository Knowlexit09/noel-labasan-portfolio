Why I Built DishHomie

Deciding what to cook every day can take longer than it should, especially when planning both lunch and dinner. DishHomie turns that routine question into a simple visual workflow: browse Filipino ulam ideas, ask the roulette to suggest one, review the recipe, and build a practical weekly plan.

The published app is branded Ano'ng Ulam? in its on-screen header, while its GitHub repository and project identity use DishHomie.

Key Features

  • 70 built-in recipe ideas: ten default dishes for each day from Monday to Sunday, with ingredients and cooking steps.
  • Lunch / Dinner selection: separate choices and confirmations for each meal in the weekly planner.
  • Animated dish roulette: spin for a suggestion, try again, view the recipe, or explicitly confirm a pick.
  • Recipe management: add, edit, delete, reorder, search, filter, and favorite dishes.
  • Weekly grocery checklist: generate a grocery view from the dishes selected for the week, with copy and checked-item controls.
  • Personalized local planning: saves custom dishes and meal selections in the same browser, with downloadable JSON backup and restore.

How It Works

Browser interfaceResponsive HTML + CSS designed around weekly day and meal selection
Client-side logicJavaScript for roulette, recipe interactions, meal choices and grocery list generation
Local persistenceBrowser localStorage and manual JSON export/import; no backend account database

DishHomie is served as a static website through GitHub Pages. Its recipe catalogue and interactive logic run in the user's browser, so the core features do not require a login or paid API.

Data, Privacy & Current Limitations

DishHomie stores meal selections, custom dishes, favorites, and checklist state locally in the browser. Information does not automatically sync across phones and computers. If browser storage is cleared, locally saved changes may disappear unless the user exported a JSON backup first.

Recipe quantities are approximate and generally intended for around 3–4 servings. Serving-size scaling, consolidated grocery quantities, cost estimates, cloud accounts, and cross-device sync are not presented as completed features.

What I Practiced

  • Translating a common everyday problem into an interactive, mobile-friendly workflow.
  • Managing selections, favorites, search results, and weekly planning state with browser JavaScript.
  • Handling local persistence and user-controlled JSON backups without requiring an account.
  • Designing simple affordances around random suggestions: the roulette proposes, while the user confirms.
  • Deploying and maintaining a public static application from its GitHub repository.
